# B03 传统算法独立基线

这个目录可整体复制到服务器，使用 Python 3.12+ 标准库运行。它绕过 Pi 和 LLM，用固定事件规则调用计算工具，作为传统算法在线控制组。

## 目录

| 文件或目录                | 用途                                                      |
| ------------------------- | --------------------------------------------------------- |
| `baseline.py`             | 事件轮询、固定规则、规划与日志入口                        |
| `snapshot.py`             | 拉取节点、链路和活跃业务，构建规划快照                    |
| `execution.py`            | 逐动作重验、路径提交、回读及 QoS 采样                     |
| `algorithms/`             | 当前计算核心副本，包含路径搜索、QoS、容量、优先级和规划器 |
| `simulator_api/`          | 公开 API 封装与 mock 样本                                 |
| `orchestration/impact.py` | 原工程的事件影响分析                                      |

## 快速运行

先验证打包是否完整。mock 只读样例，不与服务器通信：

```bash
python3 baseline.py --mode mock --startup-check --max-polls 1
```

真实服务地址只填协议、主机和端口。用团队现有方式设置 `SIM_OPEN_TOKEN`。令牌不随目录分发，也不写入运行日志。若网关要求队伍专用 Agent 标识，再设置 `SIM_AGENT_ID`。

```bash
export SIM_BASE_URL=http://127.0.0.1:10100
read -rs SIM_OPEN_TOKEN
export SIM_OPEN_TOKEN
```

连接**已经启动**的专用测试实例，先只读取快照和计算。实例 ID 从启动回执或测评工作台取得：

```bash
python3 baseline.py --mode real --instance-id 实例ID --startup-check --max-polls 1
```

用公开 API 启动一个新的参赛包测试实例并运行传统控制组。套件、场景和脚本名要与服务器部署版本一致：

```bash
python3 baseline.py --mode real \
  --start sce20261104-conf04 sce01 script-01 \
  --apply --duration 1800 --interval 5 --feedback-windows 2
```

`--start` 会请求启动场景，`--apply` 允许写入路径。确保试验期间没有另一个 Agent 或手动操作修改同一实例。附加到已运行实例默认从当前服务器时间开始轮询，可用 `--since-ts-us` 指定已知游标。启动后从启动回执的 T0 开始轮询。进程退出不会主动停止平台场景。默认采用事件触发；只有显式传入 `--startup-check` 才在首次采集到运行中业务后执行一次启动规划。默认 K=5、compare、补搜关闭、规划预算 2 秒。

## 对接与测量口径

- 负载模型包含全部运行中业务，目标来自本轮相关事件。背景占用仍进入账户。发送速率缺省按需求带宽估计。
- 站点使用由节点对推导的 flow 键，依据已核对镜像的端点 IP 对查找逻辑。快照发现重复节点 IP、同端点现路不一致、未知路径或无法展开的节点段时，暂不下发并记日志。中转角色优先使用 canTransit，字段缺省时按 ground 节点可中转处理，联调时要核对部署映射。公开查询由多次 GET 拼成，具有采集时差。
- 每步提交前重取快照，检查旧路、合法中转、静态 QoS 和按方向估计的共享容量。新事件、拒绝、不确定提交结果或回读不匹配都会中止当前执行并退出。提交超时不会自动重试，日志保留原 requestId。此入口使用进程内游标，建议每轮独立启动并留存日志。
- 提交受理和路径生效分开记录。默认采两个相隔约一秒的业务 QoS 样本，记录该 flow 上业务的实测字段及基线阈值判断。QoS 样本供联调，不替代平台官方 ServiceSim 评测日志。连续读回会影响轮询间隔；需要只验证提交时可用 `--feedback-windows 0`。
- JSONL 默认写入 `logs/`，含事件游标、快照、计划、规划函数耗时、提交请求 ID、平台回执及回读。路径与实际 QoS 仅在服务器运行后才可验证。传统算法组未调用模型；读取官方测评结果时，请将模型相关维度与业务保障、时间、连通度分开比较。
